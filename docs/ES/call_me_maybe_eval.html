01

Introducción

Mantén una actitud educada, cortés, respetuosa y constructiva durante todo el proceso de evaluación.

Identifica junto con la persona (o el grupo) evaluada las posibles disfunciones del trabajo. Tómate el tiempo necesario para discutir y debatir los problemas que hayas identificado.

Mantén siempre una mente abierta y evalúa con la mayor honestidad posible. La pedagogía solo es válida si la evaluación entre pares se realiza con seriedad.
02

Directrices

Solo evalúa el trabajo que esté en el repositorio Git del estudiante. Comprueba que el repositorio pertenece al estudiante y que se usa "git clone" en una carpeta vacía.

Verifica cuidadosamente que no se hayan usado alias maliciosos. Si el evaluador no ha completado aún el proyecto, es obligatorio leer el enunciado completo antes de la defensa.

Usa los flags para señalar un repositorio vacío, un programa que no funciona, errores de norma o trampa (nota = 0, o −42 en caso de trampa). No se permite ningún segfault o terminación inesperada — la nota final será 0 si ocurre.

También debes verificar la ausencia de fugas de memoria. Toda memoria asignada en el heap debe ser liberada correctamente antes de finalizar la ejecución.
03

Parte Obligatoria

Preliminares

Comprueba los siguientes requisitos:

  • Solo evalúa el trabajo que esté en el repositorio Git del estudiante o grupo.
  • El proyecto debe ejecutarse con uv run python -m src
  • Todos los errores deben gestionarse de forma robusta sin que el programa falle
  • Verifica que el JSON de salida sigue exactamente el formato especificado
  • Comprueba que se implementa decodificación restringida (no solo prompting)
  • Asegúrate de una validez JSON casi perfecta (salida 100% parseable)
Estructura del Proyecto y Dependencias

Verifica la configuración del proyecto:

  • Ejecuta uv sync con éxito
  • Verifica que llm_sdk está correctamente integrado
  • Comprueba que todas las clases usan pydantic para la validación
  • Asegúrate de que el programa se puede ejecutar con uv run python -m src
  • Verifica que la estructura del directorio input/ es correcta
  • Comprueba que el directorio output/ se crea durante la ejecución
Manejo de Ficheros de Entrada

Prueba el procesamiento de ficheros de entrada:

  • Verifica que el programa lee correctamente function_calling_tests.json
  • Verifica que el programa lee correctamente functions_definition.json
  • Prueba con JSON inválido en los ficheros de entrada (debe gestionarse sin fallos)
  • Prueba con ficheros de entrada faltantes (debe dar mensajes de error claros)
  • Verifica un manejo de errores adecuado sin que el programa falle
Formato del Fichero de Salida

Verifica la corrección del fichero de salida:

  • Comprueba que se crea el fichero de salida (por defecto: data/output/function_calling_results.json, o la ruta indicada con --output)
  • Verifica que el fichero contiene JSON 100% válido y recuperable
  • Confirma que el JSON sigue estrictamente el esquema esperado
  • Comprueba que cada entrada incluye exactamente: las claves prompt, fn_name y args
  • Asegúrate de que todos los argumentos requeridos están presentes y coinciden con el esquema definido
  • Verifica que los tipos de argumento y los valores permitidos cumplen con las especificaciones de las funciones
  • Confirma que no hay claves adicionales, texto ni prosa fuera de la estructura JSON
Precisión en la Llamada a Funciones

Evalúa la precisión en la llamada a funciones:

  • Prueba con prompts simples (p.ej., "suma 2 y 3")
  • Verifica la selección correcta de función (>90% de precisión esperada)
  • Comprueba la precisión en la extracción de argumentos (>90% esperada)
  • Prueba con prompts ambiguos
  • Verifica que el sistema gestiona casos límite (cadenas vacías, números grandes)

¿Alcanza la solución al menos un 90% de precisión en la selección de función?

Uso del SDK de LLM

Verifica el uso correcto del SDK de LLM:

  • Comprueba que encode y decode se usan correctamente
  • Asegúrate de que no se accede a métodos o atributos privados
  • Confirma que se usa el modelo Qwen/Qwen3-0.6B
Gestión de Errores y Robustez

Prueba el manejo de errores:

  • Prueba con JSON de entrada malformado
  • Prueba con definiciones de función faltantes
  • Prueba con prompts que no coinciden con ninguna función
  • Verifica que se proporcionan mensajes de error claros
  • Asegúrate de que el programa nunca falla inesperadamente

¿Gestiona el programa todos los casos de error de forma robusta?

Rendimiento y Fiabilidad

Evalúa el rendimiento:

  • Comprueba que todos los prompts de prueba se procesan en un tiempo razonable (<5 minutos)
  • Verifica que el 100% de las salidas son JSON válido (parseable)
  • Comprueba que la solución alcanza >90% de precisión en las pruebas proporcionadas
  • Verifica que el sistema es fiable en múltiples ejecuciones

¿Cumple la solución estos criterios de rendimiento?

Calidad del Código y Documentación

Revisa la calidad del código:

  • Comprueba que el código está bien organizado y es legible
  • Verifica el uso correcto de pydantic para la validación
  • Comprueba que el README.md explica el algoritmo con claridad
  • Verifica que el README incluye las decisiones de diseño y los retos afrontados
  • Comprueba que hay type hints y documentación adecuada

¿Son satisfactorias la calidad del código y la documentación?

Evaluación con Moulinette

Ejecuta la evaluación con la moulinette:

  1. Navega al directorio de la moulinette
  2. Ejecuta uv sync con éxito
  3. Ejecuta uv run python -m moulinette prepare_exercises --set private con éxito
  4. Ejecuta uv run python -m moulinette grade_student_answers --set private --student_answer_path <path> con éxito
  5. Verifica que la puntuación total es mayor que 0
  6. Comprueba que la evaluación se completa sin errores

¿Pasa la evaluación con la moulinette con éxito?
